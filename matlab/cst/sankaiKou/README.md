# 三开口环槽（SanKaiKou）取样与联动扫描实例

`matlab/cst/` 两个通用模板的一份完整落地：一个具体模型、一套受约束抽样规则、一份可续扫的 MATLAB–CST 联动脚本。通用配置方法见 [../README.md](../README.md)，这里只写本例特有的部分。

## 模型与参数

单元为「玻璃衬底 + PEC 环形槽 + 3 条金属桥」，环形槽减去三条桥后得到三段弧槽。可扫参数 6 个：

| 参数 | 含义 | 单位 | 范围 |
| --- | --- | --- | --- |
| `p` | 单元周期 | µm | 250–300 |
| `r` | 环形槽外半径 | µm | 100–130 |
| `w` | 槽宽（内外半径差） | µm | 35–50 |
| `g` | 金属桥宽度 | µm | 35–50 |
| `alpha` | 桥 2 方位角基准 | ° | 135–155 |
| `beta` | 桥 3 方位角基准 | ° | 135–155 |

三条桥的方位角为 0°、90°−`alpha`、90°+`beta`，于是三段弧的圆心角是

```
arc1 = 90 + beta
arc2 = 360 - alpha - beta
arc3 = alpha - 90
```

`alpha = beta = 145` 时 arc2 = 70°，与参数设置文档中的 gamma 一致；但同一组参数下 arc3 只有 55°，**arc3 才是最短弧**。`alpha = 120` 时 arc3 会降到 30°，所以长度判据不能只看 arc2。

## 约束

四条硬约束，`Dataproduce_SanKaiKou.m` 在舍入后逐条复核：

1. `p − 2r ≥ 40`：环外缘到单元边界 ≥ 20 µm
2. `r − w ≥ 60`：环内侧金属区宽度
3. `360 − alpha − beta ≥ 55`：gamma 下限
4. `L_min ≥ 35`：`L = (r − w/2)·θ·π/180 − g`，θ 取三条弧中最短的一条

第 4 条与参数设置文档存在分歧：文档按 arc2 判长度，脚本默认按真实最短弧判（`STRICT_MIN_ARC = true`）。要改回文档口径，把该开关设为 `false`，脚本会照常生成并按 arc2 过滤，同时在控制台报告有多少组真实最短弧不足。

非对称组额外要求 `|alpha − beta| ≥ 1.0°`（`MIN_ABS_ANGLE`），避免保留 1 位小数后两侧角度相同、退化回对称组。

## 400 组的构成

| 组 | p 区间 | 对称（`alpha = beta`） | 非对称 | 合计 |
| --- | --- | --- | --- | --- |
| 主区 | 250–275 | 64 | 256 | 320 |
| 边界区 | 275–300 | 16 | 64 | 80 |

参考点 `(p,r,w,g,alpha,beta) = (260,110,40,40,145,145)` 固定在主区对称组，不依赖随机抽到。

## 用法

1. 运行 `Dataproduce_SanKaiKou.m`，在同目录写出三份表：
   - `SanKaiKou_LHS_400.txt`：仿真输入表，`ID` + 6 个参数，制表符分隔、2 位小数；
   - `SanKaiKou_LHS_400_audit.csv`：带派生量（gamma、三段弧、L、`p−2r`、`r−w`）的审计表，便于先查约束再送仿真；
   - `SanKaiKou_pilot32.txt`：32 组试算点，先钉住参考点和各维极值，再按分组用 maximin 铺开。
2. 把 CST 工程副本命名为 `三开口谐振环.cst` 放在同目录（`*.cst` 被 `.gitignore` 排除，不随仓库发布）。该副本必须**不含旧求解结果**——脚本用「能不能导出数值」判断求解是否结束，模板里带着上次的曲线会让它读到旧结果。
3. 在 CST 中核对导航树里 S 参数的实际名称，改 `ParameterSweep_SanKaiKou.m` 顶部的 `S21_TREE` / `S11_TREE`。本模型是单模端口：透射 `1D Results\S-Parameters\SZmin(1),Zmax(1)`，反射 `1D Results\S-Parameters\SZmax(1),Zmax(1)`。
4. 先按 `SanKaiKou_pilot32.txt` 试算，确认曲线正常后把 `paramFile` 换成 400 组表。结果写到 `SanKaiKou_Results/<ID>_S21.txt` 与 `_S11.txt`，两列 `[频率/THz, 线性幅度]`。

## 两处与通用模板不同的判断

这两条都来自实际踩坑，改之前请先看理由。

**等待判据不依赖 `SelectTreeItem` 是否抛异常。** CST 2025 里它对不存在或尚未算完的曲线不报错，只是静默不切换视图，因此用 `try/catch` 包住它判不出求解状态（用错了还会表现为 S11 与 S21 导出成同一条曲线）。这里改成反复尝试 ASCII 导出，能读出两列数值就认为结果就绪——模板副本本来没有旧结果，导出的必然是本次求解的曲线。

**结果先写临时文件再改名。** 导出前就 `delete` 正式文件的话，重跑一组时会在导出成功前先删掉上次算好的结果，中途中断或超时就永久丢一组数据（本机确实这样丢过一组）。现在先写 `<ID>_S21.txt.part.txt`，读回校验通过才 `movefile` 覆盖，旧结果只在新数据到手时才被替换。

其余部分（单组出错不中断整体、进度与 ETA、频点密度体检、`sweep_log.csv` 续扫对账）与通用模板思路一致。

## 状态

在 MATLAB R2025b + CST Studio Suite 2025 上跑过完整 400 组：单组 31–63 s（平均 38 s），全表约 4.2 h，每组导出 2001 点、0.1–0.5 THz。其中 394 组由当前版本脚本连续完成。

脚本没做端到端理论验证：曲线是否物理正确取决于 CST 工程的端口、边界和材料设置，不取决于这两个脚本。
