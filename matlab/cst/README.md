# MATLAB–CST 参数数据与联动扫描模板

这里有两个可改造的脚本：

- `generate_parameters.m`：按依赖顺序进行条件拉丁超立方采样，舍入后复核约束、去重，再从候选池选出指定数量的样本。默认配置是 AuSRR 的 `p,r,w,d,l1,l2` 六个参数。
- `run_cst_sweep.m`：读取参数表，将所有数值列写入同名 CST 参数，逐组求解并导出配置的结果曲线。默认结果树仅是原 AuSRR 示例。

## 原始 AuSRR 随机性的判断

原代码的六列 `U` 各自是分层且随机打乱的，比直接独立均匀抽样更利于覆盖输入区间。`rng('shuffle')` 使每次结果变化，但无法直接复现。原代码按几何条件改变下界、筛除无效行、舍入，再截取最先得到的 400 行。因此**最终六个物理参数不再保证严格的拉丁超立方分层，也不服从六维长方体上的独立均匀分布**。尤其 `r` 受到 `w,d` 限制，`p` 受到 `r` 限制，`l1` 受到内环弦长限制；这些相关性是几何约束的自然结果。原代码没有去重或最大迭代次数，也没有输出分布诊断。`r_range(1)` 在采样表达式中未被显式使用；本模板的边界复核会检查每一项配置边界。

默认模板面向**覆盖可行设计空间的仿真训练集**，不是从某个现实制造分布抽取无偏随机样本。它建立多个分层候选批次，舍入后重新检查全部边界和自定义约束，去重，并用归一化距离的最远点选择提高分散度。这样仍不能保证最终表是严格 LHS；脚本打印可行率、唯一数、各列观测范围和十分位区间占用数，供检查。若要保留候选的随机分布，将 `cfg.selection` 改成 `'random'`。若要重现同一批数据，保留整数 `cfg.seed`；若要每次重新随机，设为 `'shuffle'`。

400 组相对六维网格很稀疏。例如每维仅分成 3 档也有 `3^6=729` 种组合。是否足以训练模型还取决于目标频段、共振尖锐程度、需要的预测误差和验证集表现；仅凭“随机”无法保证足够。

## 使用

1. 在 `generate_parameters.m` 顶部设置输出路径、样本数、精度、参数顺序和边界函数。新结构需要同时更新 `sampleOrder`、`outputOrder`、`lower`、`upper`、`distanceRanges`，按需更新 `extraConstraint`。边界函数可引用先前采样的参数，但不能引用后续参数。
2. 在 MATLAB 运行脚本。默认在当前工作目录得到 `parameters.tsv`。文件含 `ID` 列，其他列为参数值。检查控制台报告，尤其可行率与各参数范围。
3. 将不含旧仿真结果的 CST 工程副本命名为 `model.cst`，与参数表放在 MATLAB 当前工作目录，或在 `run_cst_sweep.m` 中设置两个完整路径。模板里保留旧曲线可能使脚本误读旧结果。
4. 在 CST 中核对参数名称、求解器、导航树名称，以及导出值是 dB 还是线性值；据此修改 `cfg.solverObject`、`cfg.solverMethod` 和 `cfg.results`。默认 `db20` 将 dB 曲线转换为线性幅度 `10^(dB/20)`，不保留相位。需要复数 S 参数或相位时，应另外配置对应 CST 导出流程。
5. 在装有 MATLAB 和 CST 的 Windows 电脑上运行 `run_cst_sweep.m`。结果位于 `cst_runs/results/<ID>/`；工程副本位于 `cst_runs/projects/<ID>/`。每组完成后才写 `complete.txt`。失败信息追加到 `failed_runs.tsv`，下次运行会重试未完成的组。

`cfg.resultWaitSec` 只限制求解器调用返回后等待结果导出的时间。若 CST 的 COM `Start` 调用本身一直阻塞，MATLAB 不能靠这个设置中断求解器。扫描脚本尚需用你的实际 `.cst` 工程和 CST 版本做端到端验证。

生成数据、CST 工程和结果文件不应提交到 GitHub；仓库只保存脚本和说明。

## 具体实例

[`sankaiKou/`](sankaiKou/README.md) 是一份完整用例：三开口环槽单元的 400 组受约束抽样与 MATLAB–CST 联动扫描。里面写清了该模型的 6 个参数含义、四条几何约束、400 组的分组构成，以及两条与上面模板不同的实测结论——求解结束的判据不能靠 `SelectTreeItem` 是否报错，结果也不该直接写正式文件。想改造模板时，先看这份用例比对着改。
